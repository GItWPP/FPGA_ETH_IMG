# 上位机快速收发与静态图像转换

目标：在同一FPGA固件、32包默认窗口和1024字节负载下，提高有效图像吞吐，缩短静态图像RGB565准备与结果显示的耗时。

## 数据流

Pillow解码/尺寸处理 → 公共NumPy RGB565编码 → UDP窗口上传/接收 → 独立整数参考逐像素检查 → 公共RGB565解码 → 原有交互预览。

UART标量编解码与算法参考模型保留，作为独立检查依据。新公共编解码模块仅依赖NumPy和Pillow，不导入视频解码器；视频复用同一实现。字节序仍为RGB565小端，颜色展开仍采用高位复制，禁止改变像素语义。

## UDP不变量

- 一个UDP数据报必须恰好包含一个应用包；直接检查MAGIC、版本、长度上限、精确报文长度及一次CRC16。错误包整体拒绝，不跨报文拼接，不通过重新编码重复计算CRC。
- 保留已连接UDP套接字与返回端点检查。每个回包payload拥有独立bytes，不能在下一次接收时覆盖。
- 窗口阶段使用非阻塞套接字；有数据直接接收，仅在暂不可读/写时使用select等待。退出窗口时无论成功、失败、取消均恢复原超时模式，控制命令继续使用现有事务接口。
- 发送暂不可写时有界等待并检查取消；接收等待最多到最近有效重试期限，有取消事件时最多50ms轮询一次。
- 截止时间最小堆替代每包遍历全部待确认请求。收到回包或重试后惰性丢弃旧堆项；每个请求保持独立期限和尝试次数，只有连续确认才滑动窗口，保护FPGA模64结果缓存。
- 结果缓冲预分配，按连续确认顺序写入，严格检查每包预期返回长度及最终总长度。滤波返回长度可小于上传长度。

## 验证

同轮保留旧上位机代码、EXE、基准结果及bitstream哈希。比较同一1080p测试图片的网络耗时、编码/解码耗时和实际GUI总耗时；计时外逐字节检查。覆盖全部65536种RGB565值、奇数尺寸、L/RGB/RGBA图片、错误尺寸。

UDP覆盖整包边界、错误版本/长度/CRC、payload中的MAGIC、重复及乱序回包、早期回包丢失、请求丢失、旧8包固件协商、有界超时、窗口取消及套接字模式恢复。完成图片算法、HOG/Band、视频与最终frozen EXE实板验收后再更新发布包。RTL及约束哈希一致时复用既有实现和仿真结果。

## 本轮结果

同一固件与32包窗口，网络基准5次中位344.296 Mbps、零重传。旧/新客户端交替各5次中位223.262/325.399 Mbps；编码/解码中位为0.018317/0.022416秒。

最终frozen EXE网络0.095014秒、349.188 Mbps，后台全流程0.140689秒，GUI更新约0.210秒。旧EXE后台总耗时1.991秒；新旧PNG与独立标量参考一致。107项Python自检、图片/HOG/Band/视频和6种frozen GUI实板测试通过。硬件未改动。

复现：`python tools/board_host_benchmark.py`。`--compare`还会加载本机tools/backups/before_host_fast/eth_image.py交替比较；该备份不属于便携源码的必需文件。
