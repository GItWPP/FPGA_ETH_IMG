## 功能与仿真

- Python：71项通过，其中7项以真实本地UDP套接字验证包边界、超时重试、错误来源及校验失败。
- 全部12个RTL自检通过；网络核心199个完整GMII事务逐字节对照，包含ARP、FCS、IP/UDP checksum、应用CRC、8种算法、完整HOG/Band流程及重复/冲突请求。
- RGMII使用官方原语模型验证32字节双向DDR顺序、EN/ER编码和转发时钟。异步邮箱验证最大1038字节、奇数checksum、读反压、忙时保护、丢弃和复位。
- 原有9个算法/协议自检保持通过；Band算法自检包含当前4张点阵图片及3个合成/变换样例。

## 速度与范围

- 原生1920×1080复制往返3.825255秒，返回4,147,200字节并与原始RGB565完全相同，重试0次。
- 有效图像吞吐1.084 MB/s，双向应用负载合计17.347 Mbps。该值不含文件转换、参考检查和预览绘制。
- 物理链路1 Gbps；首版1024字节应用块逐包请求/应答，尚未采用滑动窗口或整帧突发。实际业务吞吐与链路速率分别记录。
- Band仍为16～512 × 16～512近水平点阵；每行至少5点，末两行同步。逐项回归不代表真实码流误码率或HOG检测准确率。

## 实现与时序边界

- 综合层级包含eth_udp_stack、img_stream_top、eth_image_rx、tx_mailbox及RGMII接口，与移植方案一致。
- 6701 LUT、5397寄存器、111/128 BRAM、5 DSP；无latch，DRC无错误，综合及实现均无critical warning。
- 内部建立裕量2.842 ns，保持裕量0.017 ns；无无时钟或未约束内部端点。
- CDC无critical项。336个CDC-15分别对应RX邮箱112位、TX邮箱144位、ARP80位的稳定元数据；通过同步事件限定采样，邮箱数据保持到末字节确认。使用具体路径的最大延迟和bus skew约束，没有将时钟域整体设为false path。bus skew检查通过。
- 参考板PHY RXDLY/TXDLY和PCB走线未提供外部I/O延迟数值。保留15项缺失输入/输出延迟提示；RGMII外部接口尚未正式签核，内部收敛及功能实测不能替代板级时序参数。
