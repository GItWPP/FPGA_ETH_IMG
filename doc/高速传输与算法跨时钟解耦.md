# 高速传输与算法跨时钟解耦

本文记录v1.5的125MHz传输＋50MHz算法结构。v1.6在保留相同FIFO/RAM边界与原子缓存提交的基础上，将算法域也提升到125MHz，并保留50MHz回退固件；当前频率与实测见[算法125MHz提频](算法125MHz提频.md)。

目标：协议和原图复制使用 125 MHz，已有算法使用 50 MHz，保证逐字节结果、重试和会话检查一致。

## 时钟和模块

PHY RX 125 MHz → RX 整包队列 → 传输域 125 MHz 的协议解析、响应缓存、编码 → TX 整包队列 → GMII TX 125 MHz（保留原板卡相移）。算法域为独立的 50 MHz。

`img_async_command` 封装请求/应答/完成确认三个异步描述符 FIFO，以及请求、结果双时钟 RAM。单个命令的 RAM 所有权只在描述符提交后转移，直到完成确认前禁止覆盖。

接口沿用完整包 valid/ready、请求字段、同步 RAM 地址/数据、结果写端口和应答 valid/ready/done；新增 `algo_clk`。请求字段 72 位，应答包含命令/编号/序号/长度、原图旁路标志和 16 字节控制应答。多位字段通过异步 FIFO，不直接跨时钟采样。

## 关键时序

1. 传输域接受命令，先预取字节 0，再按每周期 1 字节写请求 RAM。普通图像 DATA 同时写入独立的暂存物理槽，禁止发送。
2. 全部请求字节写完才提交请求描述符。算法域取出描述符并向原有命令分发模块握手，所有尺寸、会话、长度、序号和缓存冲突检查继续执行。
3. 合法原图 DATA 仅由算法控制器提交计数，不再次逐字节复制。应答的原图标志允许使用传输域已复制的数据。缓存有64个逻辑槽、65个物理槽，校验成功时将目标逻辑槽与暂存物理槽原子交换；错误请求不改变映射和有效标签，旧应答仍可重发。新增物理槽单独使用1024字节RAM，不将整块64KiB缓存容量翻倍。
4. 其他算法写结果 RAM。完整计算结束后提交应答描述符，结果 RAM 保持稳定。普通图像结果由传输域搬入响应缓存；HOG/Band 结果直接由高速编码器读取。
5. 控制应答在算法域捕获最多 16 字节，再随描述符提交。应答完成后传输域发送确认，算法控制器和 RAM 才允许处理下一事务。
6. 全局复位异步置位、各域同步释放；FIFO 复位忙期间不接受事务。算法忙和网络反压都必须保留有效数据，允许缓存重发，不允许部分结果外泄。

传输侧状态：IDLE → PRIME/LOAD → REQUEST → WAIT_REPLY → [RESULT_PRIME/RESULT_COPY] → RESPONSE → WAIT_DONE → ACK → IDLE。

算法侧状态：IDLE → LAUNCH → WAIT_REPLY → [INLINE] → RESPONSE → WAIT_ACK → IDLE。

## 验证要求

不同相位和非整数比时钟；0/1/1023/1024 字节和非法长度；所有算法结果与独立参考逐字节比较；同包重试、冲突、跨会话、64 窗口回绕；输出长时间反压；执行中全局复位；综合和布局布线检查新跨时钟路径；上板验证原图吞吐与复杂算法结果。实际测量和最终时序数据完成后补入。
