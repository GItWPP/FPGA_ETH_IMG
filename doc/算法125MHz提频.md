# 算法域125MHz提频

目标：将v1.5的算法域从50MHz提升至125MHz，保持逐字节结果、HOG得分和Band采样结果一致，并保留可直接下载的50MHz回退固件。

## 时钟、接口和预期时序

- PHY RX、GMII TX、传输域继续使用125MHz；GMII TX保留板卡要求的相移。
- Clocking Wizard的clk_out2改为125MHz、0°；clk_out3继续供传输域使用。算法时钟仍通过独立端口连接，描述符FIFO和双时钟RAM继续管理所有权。
- 算法域周期从20ns改为8ns。FSM、乘加/归一化步骤、RAM读延迟和valid/ready握手的周期数保持。复位仍异步置位、各域同步释放。
- 硬件端口、命令码、模型、图像尺寸和软件协议不变。先验证125MHz原结构实现；只有实际时序不满足时才对关键路径增加流水级。

## 配置和回退

`tools/build.ps1 -AlgorithmMHz 125`为默认构建，输出project_eth/build；`-AlgorithmMHz 50`重建50MHz配置，输出project_eth/build_50mhz。可用-OutputDirectory指定其他输出目录。setup_project.tcl接受同名频率的数值参数，仅允许50或125，防止意外频率进入交付。

既有50MHz验收固件及报告保存于project_eth/build_50mhz，其中eth_img.bit可直接通过Hardware Manager回退。该目录的旧XCI与build_sources.json一起保留，避免将新时钟配置误标为旧固件的构建输入。

## 验证和测量

1. 在125MHz算法时钟下重跑完整GMII事务、窗口回绕和发送反压测试；保留非整数时钟比的专用CDC/复位测试。
2. 完整回归18项RTL自检、Python参考、实现层级、DRC、CDC、建立/保持和总线偏斜约束。
3. 同一板卡、图片、客户端与窗口，分别下载已验收50MHz和新125MHz固件。重复测量HOG/Band的RUN命令耗时，以及图像算法完整网络事务耗时。编码与参考计算放在网络计时外。
4. HOG逐项对照495个得分，Band逐条对照坐标/位值/标志，图像算法逐字节对照整数参考；视频分别记录处理FPS和跳帧。
5. 纯计算周期不变时理论耗时为原来的40%；整图事务和视频FPS还受网络、上传、回读及上位机影响，以实测为准。

最终时序、资源、同板5次中位实测与交付信息见[验证记录](验证记录.md)。
