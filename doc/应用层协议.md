# 以太网图像应用层协议 v1

网络入口为 `rtl/eth_img_top.v`；算法/命令在50 MHz域运行，MAC在125 MHz域运行。默认板卡192.168.1.12、UDP端口1234。每个UDP数据报严格承载一个完整应用包，不拼接两个包，不跨数据报拼装一个包；最大数据报1038字节，适配1500字节MTU。外层IPv4/UDP使用网络字节序，以下应用字段保留小端。

## 包布局

所有多字节数值采用小端。一个包包含 14 字节固定开销。

| 偏移 | 字段 | 长度 |
| --- | --- | --- |
| 0 | MAGIC = 55 AA 5A A5 | 4 |
| 4 | VERSION = 01 | 1 |
| 5 | CMD | 1 |
| 6 | TRANSFER_ID | 2 |
| 8 | SEQ | 2 |
| 10 | LENGTH | 2 |
| 12 | PAYLOAD | LENGTH |
| 12+LENGTH | CRC16，低字节先发 | 2 |

CRC 使用 CRC-16/CCITT-FALSE，poly=0x1021、init=0xFFFF、RefIn=false、RefOut=false、XorOut=0。覆盖偏移 4 开始的 8 字节字段和 PAYLOAD，不含 MAGIC。标准校验向量：ASCII `123456789` 得到 0x29B1。

LENGTH上限1024。MAC FCS、IPv4/UDP校验失败，或应用CRC、MAGIC、VERSION、完整长度不匹配时整包丢弃，不回包。缓存忙时也整包丢弃。UDP客户端每个数据报独立解析，超时后重发完全相同的请求；普通命令默认0.5秒、最多3次，HOG/Band运算命令使用5秒等待。发送端生成非零UDP checksum，IPv4接收端允许标准规定的零UDP checksum。

## 命令

成功应答 CMD 为请求 CMD | 0x80，TRANSFER_ID 和 SEQ 原样回显。错误应答 CMD=FF，PAYLOAD 为一个错误码字节。

| 请求 CMD | 命令 | 请求 PAYLOAD | 成功应答 PAYLOAD |
| --- | --- | --- | --- |
| 01 | PING | 空 | `55 49 4D 47 01 FF 00 04` |
| 02 | START | WIDTH:u16, HEIGHT:u16, FORMAT:u8, MODE:u8 | 空 |
| 03 | DATA | 模式0/1/2/6：RGB565图像块；模式3/4/5/7：含邻域的滤波分片；最多1024字节 | 普通模式等长，邻域模式为2×N字节 |
| 04 | END | 空 | 空 |

PING 返回 ASCII `UIMG`、版本 01、模式位图 FF（bit0..7对应八个模式）、最大块长度 0x0400。PING 不终止当前会话，但会替换最近成功应答的缓存记录；标准上位机只在 START 前发送 PING。旧固件位图07只支持三模式、3F支持六模式，新上位机在所选模式不受支持时会于START前明确提示下载新固件。

START 的 WIDTH 为 1..1920，HEIGHT 为 1..1080，FORMAT 固定为 1（RGB565），MODE 为 0（原图）、1（灰度）、2（反色）、3（彩色3×3均值）、4（彩色3×3中值）、5（Sobel）、6（Gamma暗部提亮）、7（彩色3×3锐化）。START 的 SEQ 必须为 0，成功后开启或替换当前图像会话；每次图像建议使用新的非零 TRANSFER_ID。

1080p 扩展沿用 v1 包格式和命令，PING 内容不包含最大宽高。1920×1080 需要 4,147,200 字节，默认拆为 4050 个 1024 字节 DATA，序号 1..4050，END 序号 4051。累计长度使用 32 位，无需改变包内的 16 位长度或序号字段。使用大图必须同时更新 FPGA bitstream 和 1080p 上位机，旧 bitstream 会拒绝超过其尺寸上限的 START。

自动尺寸上位机默认读取图片文件解码后的原始宽高（应用 JPEG EXIF 方向），填入 START 的 WIDTH/HEIGHT。任意宽度1..1920、高度1..1080均可，不限固定分辨率或偶数宽高。RGB565每个像素占2字节，因此像素数为奇数时图像总字节数仍为偶数。自动尺寸由上位机处理；Gamma和锐化须使用当前八模式bitstream。

第一包 DATA 的 SEQ 为 1，以后每接受一包加 1（16 位回绕）。DATA 只能使用当前会话的 TRANSFER_ID 和预期 SEQ，累计输出字节数不得超过 WIDTH×HEIGHT×2。模式0/1/2/6的图像从左到右、从上到下连续排列，不附行号或行尾填充。每个像素为 R[4:0]、G[5:0]、B[4:0]，先低字节后高字节。例如红色 0xF800 发送 `00 F8`。

### 模式3/4/5/7的DATA负载

两字节小端N，后接上行、中行、下行各N+2个原始RGB565像素。N为本包输出像素数，范围1..168；请求长度必须为6×N+14（最大1022），应答负载为2×N字节。每行片段的首末列是左右邻域，FPGA依次取三个行片段的3×3窗口计算对应中行的N个输出像素。上位机只组装原始邻域，不执行发送数据的滤波运算。

输出分片按行、从左到右传输，不允许一个分片跨越图像行。图像顶/底行和最左/右列的越界邻域均复制最近的边缘像素。FPGA检查N、负载长度、当前行剩余宽度和剩余图像输出字节数，检查通过后才开始计算、更新结果缓存。1920×1080按每片168输出像素拆为每行12包、全帧12960个DATA，END序号12961；原有模式仍为4050个DATA。

END 使用最后一个 DATA 的下一个 SEQ；仅在累计图像字节数恰好等于 WIDTH×HEIGHT×2 时成功，成功后关闭会话。END 的成功应答同样可以重发。

| 错误码 | 含义 |
| --- | --- |
| 01 | 不支持的命令 |
| 02 | 参数错误，包括 START 尺寸/格式/模式、命令参数长度 |
| 03 | 没有匹配的活动会话 |
| 04 | DATA/END 序号错误 |
| 05 | 图像数据长度错误、空/奇数DATA、滤波N/长度错误、滤波跨行、累计越界、过早END |
| 06 | 最近成功请求的同 CMD/ID/SEQ 被用于不同长度或 CRC 的请求 |

## 以太网窗口和重试

普通图像的 DATA 使用最多8包的选择重传窗口。发送 START 并收到成功应答后，可以连续发送8包；每个 DATA 结果包同时确认对应请求。只有窗口头部连续收到正确结果后才能滑动窗口、发送新包；乱序收到的后续结果仍占用窗口，避免覆盖 FPGA 中尚可能需要重传的结果。

新增 `0x05 WINDOW_INFO`（空负载），成功应答 `0x85`、8字节 `45 57 49 4E 01 08 00 04`，表示 EWIN、窗口协议版本1、最大窗口8、最大负载1024（u16小端）。上位机遇到旧固件明确返回错误1时退回单包方式；不将超时或其他错误解释为旧固件。

FPGA 在8个槽保存 DATA 结果，键包含请求源端点、ID、SEQ、长度及CRC。相同请求直接回放，不重复执行算法、不增加累计长度；相同端点/ID/SEQ但长度或CRC冲突返回错误6。成功的非 DATA 算法事务清空窗口缓存；能力查询不改变算法会话。失败命令不覆盖成功结果。START、END及HOG/Band仍使用单个请求/应答事务，它们保留最近成功应答的重试语义。

UDP客户端默认每个请求最多尝试3次，超时0.5秒；RUN命令为5秒。窗口内每个缺失结果单独计时并重发完全相同的请求。请求丢失或乱序造成的后续错误4不推进窗口，等待缺口恢复后重传；其他合法错误立即终止。所有尝试有界。复位清空队列、会话与结果缓存，主机需要新 START 重新开始整帧。

两方向各有8槽异步整包队列，满时丢弃整个请求，由超时重试恢复。完整校验后才提交包，禁止半包进入算法。实现与时序见 [滑动窗口传输设计](滑动窗口传输设计.md)。

## 像素参考运算

RGB565 扩展为 RGB888 时采用高位复制：R8=(R5<<3)|(R5>>2)，G8=(G6<<2)|(G6>>4)，B8=(B5<<3)|(B5>>2)。

- MODE=0：输出输入的 16 位原值。
- MODE=1：Y=(77×R8+150×G8+29×B8)>>8，输出 `{Y[7:3],Y[7:2],Y[7:3]}`。
- MODE=2：16 位像素逐位取反。
- MODE=3：九个RGB565像素的R5/G6/B5分量各自求和、除以9向下取整，重新拼为RGB565，保留彩色。
- MODE=4：九个RGB565像素的R5/G6/B5分量各自排序，取第5个值，重新拼为RGB565，保留彩色。
- MODE=5：对九个像素分别计算8位Y，`Gx=-Y00+Y02-2Y10+2Y12-Y20+Y22`，`Gy=-Y00-2Y01-Y02+Y20+2Y21+Y22`，`E=min(255,abs(Gx)+abs(Gy))`，输出`{E[7:3],E[7:2],E[7:3]}`。
- MODE=6：R5/B5分量输出`floor(sqrt(c*31))`，G6分量输出`floor(sqrt(c*63))`，相当于原生位宽的gamma=0.5曲线。RTL使用固定查找表。
- MODE=7：三个原生颜色分量各自计算`5*中心-上-下-左-右`，R/B钳位0..31，G钳位0..63，再拼接RGB565；边界复制规则相同。

上位机总是对照同一整数参考模型检查整帧结果，检查成功后才显示“校验通过”。原图参考面板显示 RGB565 量化后的颜色。

## HOG行人检测扩展（特征版本1）

沿用相同帧头、CRC、最大负载1024字节和停等机制，所有多字节字段小端。普通MODE=0..7不变；HOG使用独立命令。

|请求|条件/请求负载|成功应答|应答负载|
|---|---|---|---|
|0x1F INFO|空负载|0x9F|16字节：`HOG1`、u16宽320、u16高240、u8窗口宽64、u8窗口高128、u8步长8、u8特征版本1、u32模型ID|
|0x10 START|seq=0、空负载|0x90|空；建立本transfer_id会话|
|0x11 DATA|期望seq，1..1024个GRAY8字节|0x91|空|
|0x12 RUN|期望seq，空负载，已上传76800字节|0x92|u16窗口数495，计算完成后应答|
|0x13 READ|期望seq，u16 offset、u16 count|0x93|count个i32有符号窗口得分|

START后第一包seq=1，75个1024字节DATA的seq为1..75，RUN为76，首次READ为77。READ要求RUN完成，1≤count≤256且offset+count≤495；允许在会话内继续读取不同范围。得分顺序按窗口从左到右、从上到下，共33列×15行，左上位置为`(index%33*8,index//33*8)`。窗口64×128。原始得分为Q22，显示时除以2^22，正数表示默认阈值0以上候选，非概率。

GRAY8为行优先每像素一字节，与RGB565数据路径独立。上位机等比例缩放/补边生成320×240帧；只有特征提取及SVM在FPGA完成，上位机负责NMS与检测框映射。图像算法和HOG的新START成功后均终止另一路会话。

最近成功应答由两路命令共享语义：相同cmd/id/seq及长度、CRC的重复请求重发缓存，重复RUN不重新计算。另一路成功命令使旧缓存失效，任一路错误请求不破坏旧成功缓存。错误应答0xFF沿用1命令、2参数、3会话、4序号、5长度/当前阶段不符、6冲突重试；READ范围错误为2。RUN上位机超时为5秒，其他命令沿用普通超时。

当前模型7803AC83；重训练会改变ID。上位机先查询INFO并校验特征版本和模型ID，避免旧bitstream与新上位机模型混用。模块、训练与验证说明见`模块化与HOG行人检测设计.md`及`HOG与模块化验证.md`。

## Band点阵二进制解码扩展（版本1）

命令族0x2x复用相同CRC16、停等、会话及最近成功包重发机制。START成功终止图像和HOG会话，另两路START成功终止Band会话；任一路错误请求不破坏其他算法最近的成功应答。

| 请求 | 负载 | 成功应答 | 应答负载 |
| --- | --- | --- | --- |
| 0x2F INFO | 空 | 0xAF | `BND1`、u16最大宽512、u16最大高512、u8版本1、u8同步行数2、u16最大结果数4096、u32保留0 |
| 0x20 START | seq=0，u16宽、u16高，范围16..512 | 0xA0 | 空 |
| 0x21 DATA | 1..1024字节原始GRAY8，按行紧凑排列 | 0xA1 | 空 |
| 0x22 RUN | 全帧上传完成、空负载 | 0xA2 | 16字节结果头，FPGA解码完成后应答 |
| 0x23 READ | u16 offset、u16 count，1≤count≤256 | 0xA3 | count个u32采样记录，仅解码状态为0时允许读取 |

RUN结果头小端布局为：`BND1`、u16采样记录数、u8总行数、u8解码状态、u16点距Q8、u16输入宽、u16输入高、u16候选点数。状态0成功、1无有效band、2同步失败、3缓存溢出、4点距超范围、5行定位失败。非零解码状态仍返回0xA2结果头，上位机据此报告算法失败；0xFF表示参数、会话等协议层错误。

采样记录u32布局：位8..0为x，17..9为y，18为0/1，19为同步行标志，20为边界残缺标志，21为低置信标志，27..22为行号，31..28保留为0。记录按行号、x递增。同步行包含于采样记录但从数据文本中排除；各行可见长度允许不同，图像外缺失位不补齐。

512×512输入有256个DATA，序号1..256，RUN为257，首次READ为258。RUN超时5秒，其余使用原超时；重复RUN只重发结果头，不重复执行解码。算法模块、适用范围、返回位顺序及验证见`Band_FPGA设计与验证.md`。
