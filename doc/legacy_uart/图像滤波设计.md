# FPGA 图像滤波设计

目标：在 50 MHz、低有效复位、1.5 Mbps UART 链路上，增加彩色 3×3 均值、中值去噪和灰度 Sobel 边缘检测，输出尺寸保持为输入尺寸，继续支持宽 1..1920、高 1..1080。

## 算法定义

- 模式 0/1/2：原图、灰度、反色，保持原有算法和 DATA 格式。
- 模式 3：RGB565 的 R5、G6、B5 分量分别求 3×3 和，除以 9 向下取整，输出彩色 RGB565。
- 模式 4：分别排序九个 R5、G6、B5 分量，取各自第 5 个值，输出彩色 RGB565。
- 模式 5：RGB565 位复制扩展为 RGB888，`Y=(77R+150G+29B)>>8`。Sobel X 核为 `[-1,0,1;-2,0,2;-1,0,1]`，Y 核为 `[-1,-2,-1;0,0,0;1,2,1]`，输出 `min(255,abs(Gx)+abs(Gy))` 量化得到的灰度 RGB565。

图像四边复制最近的边缘像素。不缩小有效区域，不丢弃首末行列。上位机参考模型仅用于比较回传结果，显示和保存的数据来自 FPGA。

## 数据路径与分工

电脑解码图片 / RGB565 量化 → 组装包含原始邻域像素的数据包 → UART RX / CRC → 接收 BRAM → img_ctrl 组装九像素窗口 → img_pixel_proc 实际计算 → 结果 BRAM → UART TX → 电脑拼接、校验、显示。

按包应答协议不能等待后续 DATA 包中的邻行像素，否则会与电脑的等待应答互锁。因此滤波模式的每包携带三个原始图像行片段，含左右各一列邻域；电脑只取原始像素和复制边界，滤波、排序、灰度与梯度计算均在 FPGA 完成。重复传输邻域会增加串口耗时，但无需整帧 DDR、行缓存或修改已有 Vivado 工程的源文件清单。

## 滤波 DATA 负载

沿用协议版本 1、CMD=03、CRC、编号、停止等待与成功应答重发规则。PING 模式位图更新为 `3F`。

对于模式 3..5：

1. 两字节小端 `N`：本包输出像素数，范围 1..168。
2. 上行、中行、下行各 `N+2` 个 RGB565 原始像素，低字节在前。
3. 请求负载长度严格为 `6*N+14`，最大 1022 字节；成功应答 83 的负载长度为 `2*N`。

每个包的输出仅属于同一图像行。按行从左到右传输，各行从上到下传输。FPGA 校验 N、负载长度、当前行剩余宽度和整帧剩余输出字节数。START/END 使用原定义；END 以累计输出字节数等于宽×高×2 为完成条件。拒绝错误包不推进序号、行位置或图像计数；完全相同的重发包直接重发结果，不重复执行算法。

## 接口与时序

所有新增数据接口均位于 sys_clk=50 MHz 时钟域；没有新增异步输入。外部 UART 同步链和 XDC 保持现有设计。

|接口|方向（相对 img_pixel_proc）|宽度|作用|
|---|---|---|---|
|mode|输入|3|处理模式 0..5|
|in_data|输入|16|原有逐像素模式的数据|
|window_data|输入|144|左上到右下九个 RGB565，左上位于最低 16 位|
|in_valid / in_ready|输入 / 输出|各 1|仅双方为 1 的上升沿锁存输入|
|out_data|输出|16|处理后 RGB565|
|out_valid / out_ready|输出 / 输入|各 1|反压期间保持输出，握手后可接收下一窗口|

img_ctrl：读取 N → 校验 → 对每个输出像素循环读取九个原始 RGB565（每字节 WAIT/GET 对齐同步 BRAM）→ PIX_SEND 握手 → PIX_WAIT → 写结果低/高字节 → 下一像素 / 提交应答。

img_pixel_proc：IDLE → LOAD（每拍一个分量/亮度）→ 均值 RESULT，或中值 SORT（每拍一次相邻比较交换，三分量分时复用）→ CHANNEL（锁存中值并切换分量）→ RESULT，或 Sobel RESULT。原有模式仍保持单拍弹性寄存响应。输入窗口在握手时锁存，后续计算不依赖上游输入保持。

## 验证范围

先更新独立软件参考与向量，再进行处理核自检、UART 全链路仿真、1080p 计数回归；检查边界复制、跨片段、非法 N/长度/跨行、重试缓存、反压和计算中复位。综合/布局布线/时序检查通过后下载到已授权的 JTAG 目标，在 COM11 实际回传逐像素比对，并重新打包、运行独立 EXE 验证。
