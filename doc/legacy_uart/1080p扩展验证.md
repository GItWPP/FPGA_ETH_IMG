# 1920×1080 扩展与验证

日期：2026-10-21。三种模式的完整1080p实板验收已全部完成，状态 PASS。

后续上位机已改为默认自动识别任意范围内的原图尺寸，当前发布为 UART_Image_Tool_Auto.exe；本文件保留上一版需要手动选择尺寸的验收，自动尺寸行为与测试见《自动尺寸验证.md》。FPGA bitstream保持不变。

## 使用方式

启动 `tools/dist/UART_Image_Tool_1080p.exe`，选择 COM11、1500000，打开图片后选择 1920×1080 预设，或点击“原图尺寸”。默认发送尺寸仍为128×128，请明确选择所需尺寸。预览适应窗口缩小显示，传输、参考比较和保存结果采用实际发送尺寸。

需要下载本次 `project_uart/build/uart_img.bit`；旧 bitstream 上限为320×240，只更新 EXE 会收到 START 参数错误。JTAG 配置掉电失效。

## 设计变化

- uart_img_top 和 img_ctrl 的 MAX_WIDTH/MAX_HEIGHT 由320/240扩展到1920/1080。
- RGB565 协议和1024字节分块保持不变，不使用整帧FPGA缓存，仍为两个1KiB逻辑缓存。
- 一张1080p有2073600像素、4147200字节，恰为4050个DATA包；END序号为4051。
- 原有32位整帧累计长度和16位序号足够，不增加内部数据总线或缓存深度。
- 上位机宽高检查集中使用 MAX_WIDTH/MAX_HEIGHT，加入尺寸预设和原图尺寸按钮。
- 软件参考模型采用预分配输出，减少大图临时字节对象；每包单独超时，整帧传输不会因超过一分钟而触发固定整帧超时。

传输方向：电脑图片 → RGB565分包 → FPGA CRC校验/像素处理 → 分包回传 → 电脑比较/显示/保存。

## 静态图片传输时间

1.5Mbps、8N1，每字节占10位。有效数据发送加回传下限为4147200×10×2/1500000=55.296秒。实际还包括包头、停等、USB调度和软件处理；定位为静态图片传输。
