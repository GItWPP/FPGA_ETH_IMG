# 视频文件逐帧 FPGA 处理

目标：视频文件由电脑解码，图像算法和 HOG 特征/分类仍在 FPGA 执行；回传结果按帧配对显示，支持暂停、继续、停止及低延迟跳帧。

## 数据路径

```mermaid
flowchart LR
    V[视频文件] --> D[电脑 OpenCV / FFmpeg 解码]
    D --> S[按播放时钟选帧 / 等比例缩放]
    S --> P[RGB565 或 HOG 灰度帧]
    P --> U[现有 UDP 窗口 / 独立帧会话]
    U --> F[FPGA 现有图像或 HOG 算法]
    F --> R[完整结果 / CRC / 长度检查]
    R --> Q[至多一个待显示帧对]
    Q --> UI[主线程同步显示原帧和对应结果]
```

复用当前 bitstream、端点和应用命令，不增加 PL 帧缓存，不修改 RTL、引脚或时钟。每一帧使用新 transfer_id 和完整 START/DATA/END（HOG 为 START/DATA/RUN/READ）；帧之间不交错。PC 只保留当前帧、处理结果和一个待显示帧对，不排队缓存整个视频。

## 接口与状态

| 对象 | 所在线程 | 接口及职责 |
| --- | --- | --- |
| VideoReader | 视频工作线程 | 读取尺寸、帧率、帧数；跳过旧帧并解码选中帧；退出释放文件 |
| PlaybackClock | 工作线程/GUI，锁保护 | 播放时间、暂停、恢复；暂停时间不计入播放时钟 |
| VideoSession | 一个工作线程 | 每帧传输、结果配对、统计；异常关闭 socket 和解码器 |
| frames 队列 | 工作线程→GUI | 容量1，旧显示消息可覆盖，帧对不可拆开 |
| stop_event | GUI→传输层 | 50ms 接收轮询检查停止，取消后关闭 socket；下次重新 START |
| ImageViewer.update_image | GUI线程 | 更新帧时保留缩放与拖动位置，尺寸变化时重新适应 |

状态：`已加载 → 播放 → 暂停 → 播放`；播放/暂停均可进入 `停止中 → 已停止`；文件结束进入 `已完成`；异常进入 `失败`。暂停时冻结播放时钟和显示；停止操作不阻塞 GUI，未完成帧不显示。

## 播放语义与范围

- 输入本地 MP4、AVI、MOV、MKV 等视频，具体编码支持取决于随 EXE 打包的 OpenCV/FFmpeg。第一版不处理音频，不支持摄像头或网络流。
- 默认等比例缩小至 640×360 范围；可选 320×240、640×480、1280×720、1920×1080 或原视频尺寸。原尺寸仍须在 FPGA 1920×1080 范围内。保持纵横比，不强制拉伸，不放大小视频。
- 支持八种图像算法和现有单尺度 HOG 行人检测。HOG 输入保持 320×240 灰度帧，框由电脑根据 FPGA 得分筛选绘制；不代表支持通用物体类别识别。Band 保留静态图片入口。
- 实时策略按源帧率和播放时钟选取最新应处理帧，跟不上时跳过旧帧；逐帧策略保留全部帧，处理慢时播放时长相应增加。第一版时间调度按文件报告的帧率，变帧率文件可能存在播放时间偏差。
- 每帧均执行完整协议 CRC、长度与会话检查，原图模式另逐字节比对。视频中其他算法不在电脑重复计算整帧参考，避免 CPU 复算拖慢播放；静态图片保留原有完整整数参考验证。
- GUI 显示源帧率、处理帧率、源时间位置、单帧耗时、跳帧数和重试次数。左右图始终来自同一个已完成处理的源帧，禁止显示旧结果配新原图。

## 性能与验证

当前原图实测有效吞吐约49.1 Mbps。仅按 RGB565 通信估算：1920×1080约1.5帧/秒、1280×720约3.3帧/秒、640×480约10帧/秒、320×240约40帧/秒；这些是按大图吞吐推算的上限，不是视频实测承诺。滤波有邻域传输和计算开销，HOG 每帧约0.26秒的既有流程也限制帧率。

使用本项目 test_img 图片生成短视频做真实文件解码与上板验收。覆盖自动结束、跳帧/逐帧、暂停恢复、停止与再次启动、尺寸约束、断链取消及窗口缩放保持；算法参考对照在独立视频验收脚本中完成。再验证打包 EXE 的真实视频工作线程、帧配对和播放控制，记录实际 FPS，不使用预先处理的视频代替 FPGA 回传。
